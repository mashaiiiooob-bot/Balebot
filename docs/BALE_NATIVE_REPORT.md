# گزارش فنی: انتقال اجرای پروژه به زیرساخت بله

تاریخ: ۱۶ نوامبر ۲۰۲۶ · وضعیت: تحقیق + پیاده‌سازی ماژول‌های مستقل از میزبان (شاخه‌ی `bale-native`، هنوز در `main` ادغام نشده)

## ۱) نتیجه‌ی کوتاه (صادقانه)
- **بله میزبان اجرای کد یا برنامه نیست.** در مستندات رسمی فقط API ربات (پیام، فایل، وب‌هوک، getUpdates، پرداخت) و مینی‌اپ (صفحه‌ای که *خود توسعه‌دهنده* روی یک آدرس HTTPS میزبانی می‌کند) پیدا شد. هیچ اجرای سمت سرور، پایگاه داده یا میزبانی برنامه‌ای مستند نشده است.
- **یک گزینه‌ی رایگان، قابل‌اتکا، ۲۴ ساعته و داخل ایران را نتوانستم اثبات کنم.** پس به‌عنوان «VPS رایگان» فرضش نکردم.
- از طرف دیگر مشکل ریشه‌ای شبکه است نه فقط میزبانی: منبع (تلگرام) خارج از ایران است و مقصد (بله) داخل ایران. در قطع بین‌الملل این دو هم‌زمان در دسترس یک پردازش نیستند. **هیچ معماری‌ای نمی‌تواند در قطع کامل، خبر تازه‌ی تلگرام را به بله برساند؛** فقط می‌شود پیام‌ها را گم نکرد و پس از بازگشت ارتباط، خودکار تحویل داد.
- بنابراین ماژول‌های تاب‌آوری را **مستقل از میزبان** ساختم (روی هر جایی اجرا می‌شوند)، تا هر وقت میزبان مناسب پیدا شد، بدون بازنویسی منتقل شوند.

## ۲) معماری فعلی
GitHub Actions (خارج از ایران، رایگان) ← با Telethon کانال‌های تلگرام را می‌خواند ← فیلتر/AI/ضدتکرار ← `tapi.bale.ai` ← کانال بله.
وضعیت در شاخه‌ی `state` (JSON، commit هر ۶۰ ثانیه). اجرا ۵.۵ ساعته و زنجیره‌ای است.
**نقطه‌ضعف:** هر پیام مستقیم و همزمان از خارج به داخل می‌رود؛ اگر `tapi.bale.ai` از بیرون در دسترس نباشد، ارسال ناموفق می‌شود و (قبلاً) کاملاً به تلاش مجدد در همان اجرا وابسته بود.

## ۳) امکانات واقعی زیرساخت بله
سطح اطمینان: **[رسمی‌✓]** = متن کامل صفحه‌ی «مستندات بازو» که کاربر عیناً در گفت‌وگو چسباند (بازبینی‌شده)؛ **[رسمی؟]** = فقط خلاصه‌ی نتایج جست‌وجو، متن کامل را ندیده‌ام؛ **[شخص‌ثالث]** = کتابخانه/نوشته‌ی دیگران؛ **[استنباط]** = نتیجه‌ی من.
(سایت `docs.bale.ai` اجازه‌ی خواندن خودکار نمی‌دهد؛ برای همین بخش‌هایی که کاربر نچسبانده هنوز [رسمی؟] هستند.)

**فهرست کامل منوی مستندات** (از متن چسبانده‌شده): ساخت بازو، ایجاد درخواست، پیوندهای بازو، دریافت آپدیت‌ها، انواع موجود، ارسال فایل‌ها، افزایش سقف ارسال و ارسال پیام انبوه، متدهای موجود، به‌روزرسانی پیام‌ها، استیکرها، پرداخت، مستندات مینی‌اپ، مستندات سرویس ارسال پیام انبوه، قالب‌بندی متن، پیوندهای بله، دوره‌های آموزشی.
**هیچ بخشی درباره‌ی میزبانی، اجرای کد، پایگاه داده یا cloud function وجود ندارد** [رسمی‌✓، از روی منو]. ولی دو بخش «افزایش سقف ارسال…» و «سرویس ارسال پیام انبوه» وجود دارد که متنشان را ندیده‌ام؛ ممکن است سقف نرخ ارسال را تعیین کنند.

| پرسش | پاسخ | سطح |
|---|---|---|
| ۱. اجرای کد سمت سرور؟ | **خیر**: در منوی کامل مستندات چنین بخشی نیست. دریافت آپدیت فقط با getUpdates یا وب‌هوکِ *آدرس خود توسعه‌دهنده* است؛ مینی‌اپ هم صفحه‌ای است که خود توسعه‌دهنده میزبانی می‌کند | [رسمی‌✓] |
| ۲. میزبانی دائمی Python؟ | در مستندات نیست [رسمی‌✓]. میزبان‌های ایرانی صراحتاً می‌گویند ربات را روی سرور خودتان اجرا کنید | [رسمی‌✓]+[شخص‌ثالث] |
| ۳. ذخیره‌ی فایل/پایگاه داده؟ | API ذخیره‌ی داده‌ی برنامه ندارد [رسمی‌✓، از منو]. آپدیت‌ها فقط **۲۰۰۰ پیام آخر و ۲۴ ساعت** نگه داشته می‌شوند [رسمی‌✓، عین متن]. فایل‌ها با `getFile` و لینک `tapi.bale.ai/file/bot<token>/<file_path>` قابل دانلودند [رسمی‌✓]؛ **سقف حجم (۲۰MB) در متن چسبانده‌شده نیست** [شخص‌ثالث، تأییدنشده]. استفاده از چت به‌عنوان دیتابیس غیررسمی و شکننده است؛ توصیه نمی‌شود | مختلط |
| ۴. فقط پیام؟ | بله: پیام/رسانه/استیکر/ویرایش پیام/وب‌هوک/getUpdates/پرداخت/مینی‌اپ/ارسال انبوه. هیچ API پردازشی یا ذخیره‌سازی نیست؛ API بر پایه‌ی Bot API تلگرام با تغییرات جزئی است | [رسمی‌✓] |
| ۵. سرویس رسمی رایگان اجرای برنامه؟ | یافت نشد؛ منو چنین بخشی ندارد | [رسمی‌✓، از منو] |

نکات عملی (بازبینی‌شده با متن رسمی):
- **وب‌هوک** فقط روی آدرس **HTTPS** و پورت‌های **۴۴۳ و ۸۸** کار می‌کند [رسمی‌✓]؛ برای استفاده از getUpdates باید `deleteWebhook` زده شود [رسمی‌✓] (پس هر دو هم‌زمان ممکن نیست).
- آپدیت با فراخوانی `getUpdates` و `offset` بزرگ‌تر «تأییدشده» حساب می‌شود [رسمی‌✓]؛ پس **دو مصرف‌کننده‌ی getUpdates آپدیت‌های هم را می‌برند** [استنباط از همین قاعده]. `offset` منفی از انتهای صف می‌خواند و بقیه را فراموش می‌کند.
- `limit` بین ۱ تا ۱۰۰، `timeout` برای long polling [رسمی‌✓].
- پاسخ خطا همیشه JSON با `ok=false`، `error_code` و گاهی `parameters` (مثل `retry_after`) است «برای مدیریت خودکار خطا» [رسمی‌✓] → کلاینت را برای خواندن `retry_after` اصلاح کردم.
- پاسخ ۴۰۳/۴۰۴ برای توکن اشتباه [شخص‌ثالث]؛ حد پیام ۴۰۹۶ و کپشن ۱۰۲۴ نویسه [از کد موجود پروژه و منابع دیگر؛ در متن چسبانده‌شده نیست].

## ۴) محدودیت‌های اینترنت ملی (۲۰۲۶)
- قطع‌های ۱۸ دی (۸ ژانویه) و ۹ اسفند (۲۸ فوریه، حدود ۸۸ روز) گزارش شده؛ سرویس‌های داخلی روی شبکه‌ی ملی (NIN) ماندند ولی مسیر به اینترنت جهانی قطع بود. [منابع پایین]
- **مهم:** مطالعه‌ی Internet Society (قطع ژوئن ۲۰۲۵) نشان می‌دهد شبکه‌های ایران در مسیریابی جهانی «دیده» می‌شدند اما سرویس‌های داخل آن‌ها (وب، DNS، ایمیل) **از بیرون ایران در دسترس نبودند**. یعنی GitHub Actions (خارج) ← `tapi.bale.ai` (داخل) در قطع شکست می‌خورد.
- در اوج قطع، گزارش‌هایی هست که خود NIN هم موقتاً قطع بوده (منبع با اطمینان کمتر).
- تلگرام از داخل ایران فیلتر است؛ پس یک میزبان داخلی هم بدون ارتباط بین‌الملل نمی‌تواند تلگرام را بخواند.
- بله از بیرون ایران در شرایط عادی در دسترس است (آزمایش خودم و گزارش‌های دیگران)، پس معماری فعلی فقط در قطع مشکل دارد.

## ۸) هزینه‌ی نهایی
- وضعیت فعلی و ماژول‌های جدید: **۰ تومان** (GitHub Actions رایگان، SQLite، بدون سرویس پولی).
- هر میزبان داخل ایران: **احتمالاً پولی؛ قیمت را نمی‌دانم و عددی نمی‌سازم.** باید خودت از ارائه‌دهنده بپرسی.

## ۹) نقشه‌ی راه
1. (انجام شد) ماژول‌های تاب‌آوری + تست + wheelhouse.
2. وصل کردن `OutboxBale` در `poll.py` با یک پرچم (`OUTBOX_PATH`)، و ماندگاری `outbox.sqlite` (شاخه‌ی state یا cache) — **نیاز به تأیید تو**.
3. تصمیم درباره‌ی میزبان رله‌ی داخلی (ببینی کدام ارائه‌دهنده‌ی ایرانی شرایط رایگان واقعی/اعتبار آزمایشی دارد؛ من اثبات نکردم).
4. انتقال تحویل به رله‌ی داخلی؛ کلکتور خارجی فقط صف را پر می‌کند و به‌محض بازگشت ارتباط، تخلیه می‌شود.
5. تست میدانی در یک قطع واقعی/شبیه‌سازی‌شده.

## ۱۰) مجهولات و ریسک‌ها
- متن بخش‌های «ارسال فایل‌ها»، «افزایش سقف ارسال و ارسال پیام انبوه»، «متدهای موجود» (پارامترهای sendMessage/getFile) و «مستندات مینی‌اپ» را ندیده‌ام. بخش سقف ارسال برای تنظیم سرعت تخلیه‌ی صف پس از یک قطعی طولانی مهم است (الان پیش‌فرض ۱ پیام در ثانیه است، بدون مبنای رسمی).
- منوی مستندات هیچ بخش میزبانی ندارد؛ ولی اگر در آینده اضافه شود، این نتیجه باید دوباره بررسی شود.
- این‌که یک صف روی دو میزبان جدا (خارج/داخل) چطور هم‌گام شود، **تا وقتی مسیر ارتباطی بین آن‌ها نباشد، معنا ندارد**؛ در قطع کامل فقط کلکتور بدون رله می‌ماند.
- ریسک سیاسی/قانونی استفاده از زیرساخت‌ها تغییر می‌کند و در این گزارش ارزیابی نشده است.
